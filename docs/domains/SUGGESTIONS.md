# OrchAI --- Suggestions Domain

## Purpose

A `SUGGESTION` is an optional recommendation generated by OrchAI.

Suggestions support decision-making but do not authorize or execute
operations.

## Sources

Suggestions may consider:

``` text
Task State
Workflow Configuration
Role
Action
Model Capabilities
Project Configuration
Execution History
Metrics
Resource Availability
Previous Findings
```

## Structure

A suggestion should identify:

-   suggested action;
-   rationale;
-   related task;
-   related execution, when applicable;
-   required capabilities;
-   expected impact;
-   authorization requirement;
-   confidence or priority, when supported.

## Lifecycle

``` text
GENERATED
    ↓
PRESENTED
    ↓
ACCEPTED / REJECTED / EXPIRED
```

Acceptance does not bypass authorization.

## Current Implementation

The initial implementation generates a next-step suggestion from task
state. A `PLANNED` task suggests `DEVELOPER` + `IMPLEMENT`, and an
`IMPLEMENTED` task suggests `QUALITY_AGENT` + `REVIEW`.

The Orchestrator enforces execution mode before requesting
authorization: `MANUAL` treats the user-provided operation as the direct
command and does not generate a proactive suggestion, `SUGGESTED`
presents the suggestion until explicit approval, and `AUTOMATIC`
proceeds only when the configured automatic policy allows the suggested
role/action pair.

## Execution Modes

### SUGGESTED

The user decides whether to accept the recommendation.

### MANUAL

Suggestions may be limited or disabled.

### AUTOMATIC

A suggestion may lead to execution only when existing policy already
authorizes that operation.

## Invariants

1.  Suggestions are non-authoritative.
2.  Suggestions do not change task state by themselves.
3.  Suggestions do not execute operations by themselves.
4.  Accepted suggestions remain subject to authorization.
